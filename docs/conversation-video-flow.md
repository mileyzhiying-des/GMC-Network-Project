# Conversation & Video Flow — 对话与视频流程

来源：Notion「Domain Knowledge / Flows / Conversation & Video Flow」+「IN-VIDE-01 视频面诊」，2026-10-01 快照（只保留现行规则，不读历史版本）。原型和本文的差距见 `prototype-vs-notion-gaps.md`。

## 1. 案件对话房（2026-10-02 选院长+对话合并版，待写入 Notion）
- 每个案件最多一个专属房间；点［发起对话］/新建案件对话时建房（IN 室长进入房间，房间里显示系统消息"XX 进入房间 / 离开房间"）
- **建房条件**：不面诊 = 基础资料确认后；面诊 = 缴费（或免除）后；不满足时［发起对话］和抽屉"+新建案件对话"候选**完全不显示**；终态案件和作废案件没有房间
- **成员**：不面诊 = 全部 IN 室长；面诊 = 全部 IN 室长 + 全部 KR 室长 + 选定院长。不面诊案件点"增加面诊"并缴费后，KR 室长和院长才加入（缴费前要先选院长）
- **推播 / toast / 未读（2026-10-02 增量修订）**：推播对象 = 这个案件**所有操作过的室长**（只发给当天上班的）；操作过的都 OFF → 改发给**同一边当天上班的所有室长**；被 @ 的人一定收到（包括院长、不负责的室长）；院长平时完全静音（不推播、不提醒、不显示未读）
- **出现方式**：① 案件页右上角［发起对话］；② 抽屉［+新建案件对话］（候选=符合建房条件的案件）；③ 引用（候选=基础资料已确认且非终态；被引用案件还没有房间且符合建房条件→生成房间）
- 案件页头部不再有"发起视频"按钮，视频只从案件对话房内发起

## 1b. 对话窗口布局
- 标题栏右上：📁 对话中的文件（该房间发过的所有文件/照片/视频，可预览、下载）/ 🔍 / 👤 成员 / ✕（删除原来的 ≡）
- 输入框工具栏：职员间对话（Main、1:1、自建群）= ［＋］［引用案件］；案件对话房 = ［＋］［🎥 视频通话］［引用案件］
- ［＋］下拉：文件 / 照片 / 视频（三个都是上传；视频 = 上传视频文件）
- 已删除：邀请室长视频、调取 timeline、预约、演示用时钟、单独的传文件/传图片、文件库按钮
- 每条消息下面的［引用到案件］保留

## 1c. 引用案件与引用到案件（2026-10-02 增量，取代此前"引用案件"）
- 名称统一为"引用"：工具栏［引用案件］、chip"引用案件 A000xxx"、消息下［引用到案件］。工具栏：职员间 =［＋］［引用案件］；案件房 =［＋］［🎥 视频通话］［引用案件］
- 流程：点［引用案件］或输入框打 # → 选案件 → 案件 chip 挂在输入框上方（可 ✕）→ 写内容 → 发送；候选可以包含基础资料还没确认的案件
- 消息下方灰底圆角条：进行中 = 📄 引用案件 A000xxx　查看案件（蓝色链接）　［转到案件对话］（白底描边按钮）；终态 = 📄 引用案件 A000xxx　查看案件
- **发出的消息写入该案件**（取代此前"只指向、不写入"）：案件已有房间 → 进案件房，显示"发言人 ｜ 来源房间 ↗"+ 原文 + 译文，点来源房间打开那个房间并定位到这条消息；符合建房条件但还没房间 → 开房间放进去；还没到建房条件 → 先记在案件 Timeline，房间建立后带进房间；终态案件：可以挂、可以发，但不写入
- 消息下的［引用到案件］（发出之后补引用）保留：候选只有基础资料已确认、且不是终态的案件；写入效果同上
- 案件页「关联案件」tab：［查看案件］一律新标签页（进行中 → 同时展开对话；终态 → 打开附件tab）

## 1c-2. 快捷键与输入规则
- 输入框打 **@** → 选人；打 **#** → 选案件（等同［引用案件］）；**Esc** 关闭选单
- 被 @ 的人一定收到提醒，包括院长（平时静音）和不负责这个案件的室长

## 1c-3. 页面打开方式
- ［查看案件］［转到案件对话］（引用案件灰条、关联案件tab）一律新标签页打开，当前页面和对话窗口不动；［转到案件对话］= 新标签页打开该案件页并自动展开对话窗口（?case=A000xxx&chat=open）
- 在案件页里打开案例库 / 项目库 → 新标签页（?page=in-library / in-projectlibrary）；不在案件里 → 页内跳转。原型里这两个页面的入口只有侧边栏的［案例库］［项目库］两项
- 原型数据在内存里，新标签页是一份全新的演示数据，不含当前标签页里新建的案件

## 1d. 案件终态
- 对话房整理进附件：对话记录（文本）+ 📁 里文件的链接（不复制文件）+ 录像与 AI 文本；然后删除房间，对话抽屉里不再出现；作废的案件没有房间
- 附件保存期限标签：对话记录 / 录像 / AI 文本 =「结案后 3 年」；报告、基础资料等病历类 =「最后就诊起 25 年」（只显示，不做真正的删除机制）

## 1e. 院长相关的演示约定
- 原型没有院长端，只在成员面板和 docs 里体现：院长只看自己负责的案件、对话房静音、视频可自愿加入、报告由 KR 室长代为提交
- 院长的轻量账号（只看自己负责的案件）：只记录，不做

## 2. 对话抽屉
- **职员间**：Main全员、韩国室长、院长、印尼室长等固定房间；新建时多选同事——选一个人直接进已有的1:1房，选多人建自建群
- **案件**：每个案件一个固定房间，只列已建房且未结案的案件
- 对话房"成员"面板：见 1. 的成员规则

## 3. 视频通话（三条独立路径）
每条在通话结束后都自动生成 AI 转写文本 + 录像，放进案件附件，并在案件对话房推送一条消息；三条互不影响，都不改变案件主状态（院长视频面诊除外，见 `case-management-flow.md` 03 面诊）

| 入口 | 什么时候用 | 生成的附件 |
|---|---|---|
| ~~院长视频面诊~~ | 已废弃（2026-10-02）：面诊不再有视频，院长看资料口述 | — |
| 室长商谈（邀请室长视频） | 已出报告后，从案件对话房发起，只能选上传了报告的KR室长；次数不限 | 室长面诊文本(AI生成) / 室长面诊视频 |
| 对话工具栏视频 | 任何已关联案件的对话里，随时可用，次数不限；发起时弹窗选参与人（免费二次面诊也在这里约定） | 视频通话文本 #N(AI生成) / 视频通话录像 #N（编号递增） |

- 这里的 AI 转写针对**视频通话本身**，和"院长审阅材料时口述生成方案草稿"是两个不同的功能

## 视频补充（2026-10-02 增量，室长视频通话，取代此前版本）
- 🎥 只在案件对话房显示；KR 室长进入房间前灰色不可用，进入后可用；不面诊案件房间没有 KR，一直不可用
- **不预约，点了直接呼叫**；被呼叫方弹出来电：铃声 + ［加入］［拒绝］（演示按钮模拟对方加入/拒绝/来电）
- 发起时选参与人（IN / KR 室长）；院长不在呼叫名单里，但可以自愿加入（画面显示"院长可加入"）
- 室长商谈：报告卡［邀请室长商谈］→ 直接打开视频画面（不经过对话房），只能选上传报告的 KR 室长
- 画面（IN-VIDE-01 现行版）：参与人=两边室长（客人用 IN 室长的画面）；左上角参与者缩写；顶部半透明工具栏（静音 / 共享屏幕 / ［结束并归档］），两边室长都能共享屏幕；下方"AI 实时转录"：人名 + 原文 + 译文，手动输入的内容用圆角框标出并翻译；显示"录制中"
- 结束：任一室长按［结束并归档］；所有人离开超过 10 分钟自动结束并归档；结束后生成 AI 文本 + 录像 → 进附件，房间推送一条消息
- 重新加入：对话抽屉置顶红卡片"XX · 视频沟通 进行中，点击重新加入"；工作台顶部卡片只在通话进行中出现（［进入会议］）；通话结束后两者都消失。没有通话时工作台不显示这张卡（取代"显示下一场预约会议"）
- 日历没有"视频沟通"类型

## Integrations & APIs（背景，来自 Notion「Integrations & APIs 外部服务与接口清单」2026-10-02；选型参考，不是最终决定；原型不接任何真实服务）
- 原则：自己只做规则层（建房时机、成员、推播对象、终态导出后删房、引用写入案件、保存期限）；通用功能用服务商 SDK；供应商越少越好；资料最终存回自己的系统
- **方案 A（推荐）**：Stream（Chat + Video，支持来电 ringing、云端录像、字幕/转录）+ Soniox（韩 ↔ 印尼即时双向翻译）+ LLM（消息翻译/视频内输入翻译/会后整理）+ Supabase（登入、资料库、文件存储，录像也可存 S3 / R2）
- **方案 B**：Agora（RTC + Chat + Real-Time STT 含翻译，支持 id-ID / ko-KR，亚洲连线强）+ LLM + Supabase；注意即时翻译目前是 Beta
- 注意事项：数据存放地区与隐私政策公开服务商；客人出现在视频里需同意并显示"录制中"；服务商副本导出后要删；录像访问权限只有 IN/KR 室长、KR 院长、管理员；即时翻译先用真实韩语+印尼语录音实测；翻译失败至少显示原文；用 webhook 接回结果；API 密钥只放服务器；翻译/转录做成可替换的一层
- 待确认：选定方案（实测后由开发/老板决定）、各服务数据区域与价格、消息翻译是否需要中文
