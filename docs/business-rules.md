# 业务规则（Domain Knowledge 导出）

来源：Notion「GMC Network」/ Domain Knowledge / Client & Case Rules + Status Dictionary，导出时间 2026-09-29（"案件流程对齐"更新后，覆盖 2026-09-23 版本，历史版本见 Notion Change Requests）。

## 客户与案件的关系
- 客户档案（Client）是独立于案件（Case）的持久记录：一个客户一生可以有多个案件。Case1 完成后，Case2 是新案件，不是"关联案件"这种特殊机制。
- 客户详情页结构：正在进行案件（仅未结案的，链接进各案件）/ 基础信息（姓名、特别备注、性别·出生年月、病史过敏史、护照信息、联系方式，全部可改；隐私协议仅可查看不可改）/ 医美史 / Timeline（仅建档、基础信息修改、Case 开始、Case 结案，不含案内细节）。

## Timeline 与修正规则
- 客户级 Timeline 记录：建档、修正、每个案件的起止时间（进行中案件显示"进行中"）。
- 案件级 Timeline 是独立的一份，记该案件内部的具体过程。
- **统一格式（2026-09-23 更新）**：`进程　状态　「操作人」　日期时间`（空格 + 「」括操作人）。
  - ⚠️ 已废弃：旧格式 `进程名／具体做了什么／谁／日期时间`（／分隔）。
- 当室长修正客户原填字段（如医美史、已选院长）时，室长的修正直接覆盖成为定论，不做"客户填写 vs 室长修正"两个版本对比展示；谁改的、改了什么，走 Timeline 的"修正"条目留痕。

## ID 规则（2026-09-23 新增）
- 预约到访阶段：Reservation ID（6 位数字 + REV）。
- 基础资料确认后：Case ID（英文 + 6 位数字，如 A000001）。
- 待确认：Reservation ID 在 Case ID 生成后是作废还是保留为历史字段继续挂在案件上——还没定。

## 案件状态与阶段（2026-09-29 更新）
案件不是建档时定死一个状态，而是由系统动态推算所处阶段。完整状态机（含面诊细分、施术预约、结算/退款分支）见 `case-management-flow.md`；这里是总纲：

```
待访问 → 接待中（生成 Case ID）→ [面诊分支] → 项目确认中 → 待确认施术时间（仅有赴韩项目）
  → 待付款 → 已付款（= 等待施术，可停留）→"已到医院"触发 → 赴韩施术中 / 本地管理中（并行）→ 已结案
```

- 术后管理阶段支持"事件"机制：案件未结案期间出现的并发症（如异常肿胀），走"症状上报 → 紧急视频复诊 → 继续观察/需二次赴韩"，作为嵌套在当前案件里的事件记录，不需要为此新开一个案件。**这个机制原型里完全还没实现。**
- 终态共4种：已结案 / 已结案（部分退）/ 已取消（取消原因：预约取消｜面诊取消｜全额退款）/ 仅出报告。⚠️ 已废弃："已取消预约""已取消（全退）"两个独立终态命名，已并入"已取消"+取消原因字段。

案件管理列表 Tabs（UI 分组，≠ 状态本身，共 7 个）：全部 / 预约到店 / 面诊安排 / 赴韩施术 / 本地管理 / 已结案 / 已取消。tab 归属规则：流程自然走完、没有取消动作 → "已结案"tab（已结案/已结案(部分退)/仅出报告）；中途有取消动作 → "已取消"tab（预约取消/面诊取消/全额退款）；注意一个 tab 里可能包含好几个具体状态值，不是一一对应。

## 费用与决策边界（2026-09-29 更新）
- 面诊费与赴韩定金是两笔独立收费；只面诊不赴韩的客户只付面诊费。
- 是否需要面诊：由印尼室长和客户沟通诉求后决定。不需要则可直接做本地项目（项目确认中→待付款→…），韩国侧完全看不到这个案件；之后可通过"增加面诊"发起面诊，此时案件对韩国侧可见。韩国侧看到过的案件，面诊取消后仍可见，显示为"已取消"。
- 施术时间：IN室长提交（可首选+备选），KR室长确认；确认前为暂定。协调在案件对话中进行，改时间由IN室长操作（需与客人确认）。付款后可修改至施术前2周。
- 面诊形式（视频还是书面）：由韩国室长决定，不是印尼侧或客户提前选的。
- 二次面诊收费还是免费：由印尼室长判断（可与韩国室长商议）——收费走"再次面诊"按钮，免费在案件对话中约定；已结案案件的术后面诊走01预约流程新建案件，免除面诊费。
- 面诊取消时面诊费由当地自行处理，系统只记录状态。
- 加项生成新结算单，案件主状态不变；退款按项目判定；更换项目 = 加项 + 原项目退款，韩国发生韩国改、印尼发生印尼改。
- 是否需要赴韩施术：由院长在面诊后决定；客户再自主决定是否愿意赴韩。
- 术后管理阶段具体需要哪些项目：由院长在韩国施术当下决定，不是印尼室长决定的。
- **结算结构**：赴韩项目收预付金 + 尾款（尾款赴韩后付），本地项目收全款；即使两边一起收款，账单也要分开列（赴韩项目韩元、本地项目印尼盾）。⚠️ 具体预付比例仍未定（业务方确认中），原型里的 30% 只是演示占位数字。
- **项目快照**：项目被选进案件时，把当时的项目ID、名称、价格、币种复制一份存进案件；之后项目库改价/改名/停用都不影响已选项目；结算后不可更改。系统只记录收没收款，不处理实际收款。

## 施术阶段的国家边界
- 韩国项目的施术是韩国那边操作的，和印尼无关：印尼侧在施术链里对韩国项目**完全只读**（只能看名称和完成状态，不能勾选/编辑/排序）。
- 印尼项目印尼室长可以正常操作：批量标完成/未完成、编辑改名、调整顺序。
- 如果韩国那边中途更换了项目，展示原项目名划掉 + 标注"更换为 XX 项目"；⚠️ 已废弃：不影响案件本身停留在"赴韩施术中"——2026-09-29 改为"更换=加项+原项目部分退款"，见分支7。
