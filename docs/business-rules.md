# 业务规则（Domain Knowledge 导出）

来源：Notion「GMC Network」/ Domain Knowledge / Client & Case Rules + Status Dictionary，导出时间 2026-09-30（"持有项目/案件结案/赴韩施术调整"更新后，覆盖此前版本，历史版本见 Notion Change Requests）。

## 客户与案件的关系
- 客户档案（Client）是独立于案件（Case）的持久记录：一个客户一生可以有多个案件。Case1 完成后，Case2 是新案件，不是"关联案件"这种特殊机制。
- 客户详情页结构：正在进行案件（仅未结案的，链接进各案件）/ **持有项目**（2026-09-30 新增，只列剩余>0的项目，术后管理置顶，没有持有项目时不显示这张卡）/ 基础信息（姓名、特别备注、性别·出生年月、病史过敏史、护照信息、联系方式，全部可改；隐私协议仅可查看不可改）/ 医美史（2026-09-30 分两块："案件记录"客人自报的过往医美史+本院所有案件、"本院项目记录"按项目分组展开购买批次和使用记录）/ Timeline（仅建档、基础信息修改、Case 开始、Case 结案，不含案内细节）。

## Timeline 与修正规则
- 客户级 Timeline 记录：建档、修正、每个案件的起止时间（进行中案件显示"进行中"）。
- 案件级 Timeline 是独立的一份，记该案件内部的具体过程。
- **统一格式**：`进程　状态　「操作人」　日期时间`（空格 + 「」括操作人）。
- 当室长修正客户原填字段（如医美史、已选院长）时，室长的修正直接覆盖成为定论，不做"客户填写 vs 室长修正"两个版本对比展示；谁改的、改了什么，走 Timeline 的"修正"条目留痕。

## ID 规则
- 预约到访阶段：Reservation ID（6 位数字 + REV）。
- 基础资料确认后：Case ID（英文 + 6 位数字，如 A000001）。
- 待确认：Reservation ID 在 Case ID 生成后是作废还是保留为历史字段继续挂在案件上——还没定。

## 案件定义与持有项目（2026-09-30 新增，核心规则变化）
- **一个案件 = 一次到店或一次赴韩旅程**。赴韩案件：KR标记"施术完成"即结案；只做本地项目的案件：本次使用完成即结案（当天不用也可直接结案）。
- 已到医院 / 付清尾款 / 施术完成，由KR端操作，IN端只显示状态。
- 项目库本地项目新增分类"术后管理"：和普通本地项目一样结算后转为客户持有项目，在持有列表中置顶。来源：KR室长整理可选范围时一并写入、在印尼结算；到韩国后需增加的由韩国侧补加，韩国当场代收、两边对账（暂定），标注"KR代收"。
- 使用术后管理项目的新案件自动关联原赴韩案件，对韩国侧可见（只读），跟踪到这批术后管理项目用完。
- 持有项目：按个数购买；只能用在同一项目上，不能换抵；多批时先扣最早购买的；使用它的案件或项目被取消时次数退回持有（不退钱）；暂不设有效期。
- 本地项目可打折（IN室长填折扣，可写备注），结算单同时显示原价和折后价。
- 退款：只有赴韩项目可退（退定金）；本地项目（含术后管理）一律不退，未使用的也不退（涉及医疗纠纷风险）。
- 韩国施术没有次卡。
- 在赴韩案件里追加的普通本地项目直接转为客户持有，不影响该案件。
- ⚠️ 已废弃：术后管理阶段支持"事件"机制（症状上报→紧急视频复诊→…）——赴韩案件施术完成即结案，术后并发症改为新建案件走面诊（免面诊费），之后按正常流程。

## 案件状态与阶段
案件不是建档时定死一个状态，而是由系统动态推算所处阶段。完整状态机见 `case-management-flow.md`；这里是总纲：

```
待访问 → 接待中（生成 Case ID）→ [面诊分支] → 项目确认中 → 待付款 → 已付款
  → 有赴韩项目：递交施术日期 → 待确认施术时间 → 等待施术 → 赴韩施术中(已到医院触发) → 施术完成(KR标记) → 已结案
  → 只做本地项目：本地项目转客户持有 → 管理进行中(待使用) → 使用持有项目/本次不使用 → 已结案
```

- 终态共3种（2026-09-30 最终版，按"客人得到了什么"推算，退款不影响结局）：已结案（完成施术/管理，或本次买了本地项目）/ 仅出报告（只有面诊报告）/ 已取消（取消原因：预约取消｜面诊取消｜管理取消｜未购买未使用）；另有独立的财务结果字段：无收入 / 仅面诊费 / 有项目收入 / 全额退款，以标签显示。

案件管理列表 Tabs（UI 分组，≠ 状态本身，共 8 个，另有"有退款"筛选）：全部 / 预约到店 / 面诊安排 / 赴韩施术 / **本地管理**（选择项目、本地管理，原"管理进行中"更名）/ 已结案 / 仅出报告 / 已取消。各状态归属和颜色见 `case-management-flow.md`"状态总表"。

## 费用与决策边界
- 面诊费与赴韩定金是两笔独立收费；只面诊不赴韩的客户只付面诊费。
- 是否需要面诊：由印尼室长和客户沟通诉求后决定。不需要则给两个入口——「持有项目使用」/「新增项目」（只显示本地项目），韩国侧完全看不到这个案件；之后可通过"增加面诊"发起面诊，此时案件对韩国侧可见。韩国侧看到过的案件，面诊取消后仍可见，显示为"已取消"。
- 施术时间：付定金后，IN室长在KR已开放的日期里选首选+备选**日期**（不选具体时间），KR室长定具体时间并回复；确认前为暂定。协调在案件对话中进行，改日期由IN室长操作（需与客人确认）。确认后可修改至施术前2周，KR排不上新日期不自动取消，只有IN室长手动"无法协调"才取消。
- 赴韩项目可选范围：由KR室长在出报告时给出（含项目备注/整体备注，如相冲项目），术后管理项目也一并写入，不需经过院长；IN端赴韩项目（含术后管理）只能在范围内选；范围外在对话里请KR室长补加（免费），需重新商谈才走再次面诊。
- 意向项目与预算：基础资料里的意向项目（必填）和预算（选填）对韩国侧可见，用于KR室长整理可选范围。
- 面诊形式（视频还是书面）：由韩国室长决定，不是印尼侧或客户提前选的。
- 二次面诊收费还是免费：由印尼室长判断（可与韩国室长商议）——收费走"再次面诊"按钮，免费在案件对话中约定；已结案案件的术后面诊走01预约流程新建案件，免除面诊费。
- 面诊取消时面诊费由当地自行处理，系统只记录状态。
- 加项：赴韩项目只能从KR可选范围里选；案件已有赴韩项目则并入现有排期，不用重新约；还没有则付款后走施术日期流程。案件主状态不变；退款只对赴韩项目有效；更换项目 = 加项 + 原项目部分退款，韩国发生韩国改、印尼发生印尼改。
- 是否需要赴韩施术：由院长在面诊后决定；客户再自主决定是否愿意赴韩。
- **结算结构**：赴韩项目收预付金 + 尾款（尾款赴韩后付），本地项目收全款；即使两边一起收款，账单也要分开列（赴韩项目韩元、本地项目印尼盾）。⚠️ 具体预付比例仍未定（业务方确认中），原型里的 30% 只是演示占位数字。
- **项目快照**：项目被选进案件时，把当时的项目ID、名称、价格、币种复制一份存进案件；之后项目库改价/改名/停用都不影响已选项目；结算后不可更改。系统只记录收没收款，不处理实际收款。

## 施术阶段的国家边界
- 韩国项目的施术是韩国那边操作的，和印尼无关：印尼侧在施术链里对韩国项目**完全只读**（只能看名称和完成状态，不能勾选/编辑）；已到医院/付清尾款/施术完成三步同样由韩国侧操作。
- 如果韩国那边中途更换了项目，展示原项目名划掉 + 标注"更换为 XX 项目"（更换=加项+原项目部分退款，见分支7）。
- 本地项目（含术后管理）印尼室长可以正常操作（填个数/折扣/备注），完全不受"施术顺序"之类的排序约束——结算后已经离开案件、转为客户持有。
