## A. 状态机总览 / Glossary / Client & Case Rules（全局规则）
| # | 原型现状 | Notion 现行 |
|---|---|---|
| A1 | 仍有 Reservation ID（6位数字+REV：`generateReservationId`、`c.reservationId`、案件标题/Toast/Timeline 引用）；Case ID 在基础资料确认时才生成，待访问/接待中的案件没有 Case ID | Case ID 在预约时生成，一直用到结案；**不再有 Reservation ID**；取消的预约也保留 Case ID（已取消·预约取消）；预约占位不生成编号 |
| A2 | 发起对话、+添加本地管理、附件tab、引用/新建案件对话的候选、关联下拉的候选，都用 `c.caseNo` 判断 | 这些功能以"基础资料已确认"为开关（Case ID 提前后 `caseNo` 不能再当开关）；取消接待只在确认前显示 |
| A3 | [面诊取消] 只出现在"待缴费"那一张卡上；"待确认面诊时间""等待面诊"阶段没有取消入口 | 面诊取消在"面诊进行中"之前都可以操作（面诊预约含待确认面诊时间、等待面诊）；面诊进行中之后不能取消 |
| A4 | 面诊取消后"是否做本地项目"是面诊tab里的内联卡片 | 弹窗"是否做本地项目？" |
| A5 | 本地管理一旦"使用项目"后，没有入口在同一次到店里继续选购/使用 | 本地管理进行中：同一次到店里可以继续选购或使用项目 |
| A6 | "模拟韩国更换项目"只给原项目打 `replacedBy` 标记；已更换的项目还能被标完成/当作未开始 | 更换项目 = 加项 + 原项目退款（韩国发生由KR操作、印尼发生由IN操作）；KRItem"已更换"是最终状态（原项目名划线+更换为XX） |
| A7 | 术后管理持有项目没有"进行时间"字段；"施术完成时KR确认术后管理项目并标注进行时间"没有演示；持有项目使用时术后管理只做了置顶，没有按进行时间排序 | KR 在施术完成时确认术后管理项目（可修改）并标注每项进行时间；使用时术后管理置顶并按进行时间排序 |
| A8 | 使用术后管理项目会自动关联原案件（已做），但"对KR可见（只读）、一直跟踪到这批用完"没有 KR 端展示；`visibleToKR` 只是字段 | 使用了术后管理项目的本地案件通过关联对KR只读可见，跟踪到这批术后管理项目用完 |
| A9 | "无法协调"只取消赴韩项目（术后管理项目结算后已转持有，不在案件里） | 无法协调 → 取消赴韩项目**和术后管理项目** + 退款 |
| A10 | 免除面诊费需室长手动选原因；关联案件时不会自动预填 | 术后面诊/复诊（原案件已结案）、面诊后过几天才决定做（延续既往面诊）：新案件关联原案件，面诊费免除（术后复查 / 延续既往面诊） |
| A11 | ⚠️ 持有项目卡片现在显示全部项目（含已用完、已退款的批次） | ⚠️ 状态机总览 HoldingBatch 有"已用完/已取消"变体；IN-CLNT-01 却写"只列剩余>0的项目"——Notion 两处互相冲突 |
| A12 | 无对应 | Notion 新增的待确认（原型都没涉及）：赴韩定金比例（原型暂用30%，一致）；KR代收术后管理项目的对账方式；赴韩取消时定金中没退的部分归印尼诊所还是韩国医院 |
