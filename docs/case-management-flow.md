# Case Management Flow — 案件状态流程

来源：Notion「Domain Knowledge / Flows / Case Management Flow」+「状态机总览 State Machines」，2026-10-01 快照（Notion 已把旧规则移到各页下的「📦 历史版本」，本文只保留现行规则；**不读历史版本**）。
状态名称、颜色、小状态、流转规则以「状态机总览」为准；术语见「Glossary」。**原型和本文不一致的地方见 `prototype-vs-notion-gaps.md`**，改原型前先看那份清单。

## 00 总览
```
预约（01）→ 接待（02）→ 是否需要面诊？
  ├ 否 → 本地管理（07）
  └ 是 → 面诊（03）→ 项目确认（04）
                       ├ 不做项目 → 仅出报告
                       ├ 只做本地 → 支付（05）→ 本地项目转持有
                       └ 含赴韩项目 → 支付定金（05）→ 赴韩施术（06）→ 已结案
结案规则见 08；特殊情况见 09
```
**基本规则**
- **一次预约 = 一个案件**：同一天、同一次到店做的所有事都在同一个案件里；另一天来要重新预约、开新案件；同一客户可同时有多个进行中的案件
- **Case ID**：客户提交预约 / 室长代约时立即生成（英文+6位数字，如 A000001），一直用到结案；15分钟预约占位不算案件、不生成编号。**不再有 Reservation ID**
- **基础资料确认**是很多功能的开关：确认后才显示发起对话、+添加本地管理、增加面诊；确认前才显示取消接待
- **关联案件tab（2026-10-01，待写入 Notion）**：有关联才出现（附件tab前面），分"之前关联"（本案件关联了谁）/"后续关联"（谁关联了本案件，系统自动生成）；每条显示 Case ID / 关联原因 / 日期 / 当前大状态，可展开看被关联案件的只读摘要（复诊：日期、面诊结论或报告摘要、使用的项目、当前状态；术后管理：使用的术后管理项目、第几次、完成状态；延续既往面诊：沿用了哪份报告、选了哪些项目、当前状态），最下方［查看完整案件］（返回走 goBack）；完全只读，原案件即使已是终态也照样显示，不改变其状态/财务/结局，其 Timeline 不新增记录
- **关联**（只用于不同天的案件之间）：接待时在基础资料选"关联之前案件"+ 原因（复诊 / 术后管理 / 延续既往面诊），由室长操作；新案件显示"关联：A000010（复诊）"，原案件显示"后续关联案件"；复诊/延续既往面诊时原报告自动带入附件；系统会提示"可能与 XX 相关"；使用某案件的术后管理项目时自动关联；关联不影响任何一方的状态

## 状态机总览（案件主状态，两层）
大状态显示在案件列表状态列 + 案件页顶部"当前状态"；小状态只显示在对应 tab 卡片的绿色字一行。

| 大状态 | Variant | 小状态 | 怎么进入 | Tone | 列表tab |
|---|---|---|---|---|---|
| 待访问 ★ | Booked | — | 预约生成Case ID | Beige | 预约到店 |
| 接待中 | Reception | — | 室长点"到访"；取消接待回待访问 | Beige | 预约到店 |
| 面诊预约 | ConsultBooking | 待缴费 → 待确认面诊时间 | 基础资料确认并选"面诊"（沿用原报告则不进入，直接项目确认中） | Yellow | 面诊安排 |
| 等待面诊 | ConsultWaiting | ✓ 面诊时间已确认（时间+倒计时） | KR回复视频面诊+时间 | Yellow | 面诊安排 |
| 面诊进行中 | Consulting | 视频路径"通话中"；书面路径"书面面诊中" | 进入视频 / KR 选书面（待写入 Notion） | Yellow | 面诊安排 |
| 等待报告 | ReportPending | 等待室长提交报告 | 视频结束（只有视频路径会进入；待写入 Notion） | Yellow | 面诊安排 |
| 项目确认中 | Planning | 待付款 | 报告出来（"已出报告"为事件）；付完款才进下一阶段 | Yellow | 面诊安排 |
| 施术预约 | TreatmentBooking | 待确认施术时间 | 付款完成（选日期→递交） | Blue | 赴韩施术 |
| 赴韩施术 | Treatment | ✓ 施术时间已确认 → ✓ 已到医院 | KR确认施术时间；已到医院由KR标记 | Blue | 赴韩施术 |
| 选择项目 | Selecting | — | 本地案件：基础资料确认并选"不面诊"（持有/使用/选购/付款都在此状态内） | Green | 本地管理 |
| 本地管理 | LocalCare | — | 本地案件：使用项目 | Green | 本地管理 |
| 仅出报告 | ReportOnly | — | 终态（系统推算） | Brown | 仅出报告 |
| 已结案 | Closed | — | 终态（系统推算） | Gray | 已结案 |
| 已取消 | Cancelled | — | 终态（系统推算） | Gray | 已取消 |

- 颜色单独做成属性 **Tone**：Beige★ / Yellow / Blue / Green / Brown / Gray
- 案件列表 tab（8个）：全部 / 预约到店 / 面诊安排 / 赴韩施术 / 本地管理 / 已结案 / 仅出报告 / 已取消；tab 是 UI 分组，不是状态本身

### 小状态行（SubStatus）
- 完成（✓ 绿）Success：面诊时间已确认、报告已出、施术时间已确认、已到医院
- 等待（灰）Waiting ★：待缴费、待确认面诊时间、待付款、待确认施术时间、等待室长提交报告、通话中、书面面诊中、待递交施术日期
- 注意（⚠ 黄）Warning：施术时间变更待确认、KR已标记无法施术
- 文字内容替换进去，组件只有这3种样式

### 其他组件的状态
- **ConsultFee 面诊费卡**（面诊资料tab，每一轮面诊各有一个）：待缴费★ → 已缴费（IN标记）/ 已免除（必选原因）/ 已取消（面诊取消，只作记录不影响后续）
- **RoundTab**：面诊2次以上才出现"第1次/第2次"切换，默认最新一次；二次面诊不改主状态，流程同第1次，结束多一步"有无变动"
- **Settlement 结算单**（项目列表tab）：待付款★ → 已付款 → 部分退款 / 全额退款；**每张结算单一个2级tab（第1张/第2张…，默认打开最新一张，样式同面诊轮次切换），tab上方一行汇总：项目合计 / 已收定金 / 已退金额 / 应付尾款（跨所有结算单）**（2026-10-01，待写入 Notion）
- **Schedule 施术日期卡**（赴韩施术tab顶部）：未递交（选日期）★ Draft → 待确认施术时间 Pending → 施术时间已确认 Confirmed ⇄ 变更待确认 Changing → 已到医院 Arrived（之后 IN 不能再变；只有 KR 在韩重新预约时可回到已确认）；**案件主状态直接读取这里，不重复记录**
- **KRItem 赴韩项目行**（IN只读）：未开始★ → 已完成 / 已取消 / 已更换（原项目名划线）；三个都是最终状态
- **ItemFlag 项目黄色小标签**：无★ / 时间变更待确认 / KR已标记无法施术；任一项目带标签（或已更换）→ 列表 Health = 非正常
- **LocalItem 本地管理项目行**：进行中★ → 已完成 / 已取消（次数归还）
- **HoldingBatch 持有项目批次**：未使用★（显示退款按钮）/ 部分使用 / 已用完 / 已取消（已退款）
- **Slot 预约占位**：占位中★（半透明+倒计时）→ 已提交（实色预约来访，生成Case ID）；超过15分钟/室长取消 → 色块消失
- **案件列表辅助标签**：Health 正常★/非正常；LocalBadge 不显示★/本地管理进行中；Finance 无收入★/仅面诊费/有项目收入/全额退款；CancelReason（只在已取消时）预约取消★/未到店/面诊取消/管理取消/未购买未使用

### 流转规则（能往哪里变、不能往哪里变）
- 终态不能重新打开；客人再来 = 新预约、新案件（可关联）
- 接待中 → 待访问：只能在基础资料确认前通过"取消接待"；确认后不能回到待访问
- 待访问 → 已取消（未到店）：过预约时间30分钟未点"到访"系统自动判定，室长也可提前手动标记；不能撤回，客人后来则重新预约（2026-10-01）
- 面诊各阶段只能往前走；二次面诊不改主状态
- 增加面诊：付款前 → 主状态进入面诊预约；付款后 → 子流程，主状态不变
- 项目确认中 → 施术预约：只有付完款才能进入；未付款可以重选项目
- 施术预约 → 赴韩施术：只由 KR 确认时间触发；无法协调可从这两个状态走向本地管理或仅出报告
- 已到医院之后：IN 不能再改日期、不能取消项目；只有 KR 能发起无法施术 / 更换项目 / 在韩重新预约时间（KR 改时间后回到"施术时间已确认"，客人再到医院时重新标记"已到医院"）；退款金额由 KR 判断、IN 操作（2026-10-01）
- 本地案件：选择项目 → 本地管理（点使用触发）；本地管理中的项目全部标完 → 系统自动判结局
- ConsultFee：待缴费 → 已缴费 / 已免除 / 已取消，三者都不能再变；Settlement 只能往前；KRItem、LocalItem 的结果都是最终状态，已完成的赴韩项目不能取消；HoldingBatch 使用被取消时次数归还（可从部分使用/已用完往回变），只有"未使用"能变成"已取消"（退款）
- 面诊取消：在"面诊进行中"之前都可以操作（面诊预约、等待面诊）；面诊进行中之后不能取消；出报告后改用"客人不做项目"
- 本地管理进行中：同一次到店里可以继续选购或使用项目

## 01 预约
- **新客人（室长发链接）**：电话/到访预约 → 室长发链接 → 日历出现15分钟"预约占位" → 客户提交 → 生成 Case ID → 待访问；超时未提交，占位自动消失（链接仍有效）；室长可"取消占位"
- **新客人（官网自助）**：客户从诊所官网打开链接 → 占位 → 提交 → 生成 Case ID → 待访问（公开预约页设计暂时搁置）
- **老客人**：客户自主预约，或室长代约，不经过占位，直接生成 Case ID → 待访问
- **预约取消**：待访问 → 取消预约 → 选择原因 → 已取消（预约取消），资料保留；日历事件消失
- **未到店（No Show，2026-10-01）**：过了预约时间30分钟还没点"到访" → 系统自动判定（室长也可提前手动标记）→ 已取消（未到店）；日历事件保留在原位并显示删除线"未到店"；客人之后才来，不撤回，重新约一个预约来访（新案件）；原型有演示按钮「模拟时间超过30分钟」
- 详细页面见 IN-DASH-01 工作台

## 02 接待
- 室长点"到访" → 接待中（"客户到访"不单独设状态）
- 填写基础资料（必填：메타뷰、照片、视频、苦恼、希望预期、意向项目、面诊需求；选填：预算、关联之前案件、上传附件）
- **取消接待**（防误点）：确认前可点 → 弹窗确认 → 回到待访问，内容不保存，日历恢复原色，Timeline 记录
- 确认后：选"面诊" → 面诊预约（03）；选"不面诊" → 选择项目（07）
- **延续既往面诊（2026-10-01 修正，待写入 Notion；取代此前"三选一"的写法）**：关联原因选"延续既往面诊"且被关联案件有面诊报告时，按距原报告日期判断：
  - **超过 1 个月** → 锁定：只能"面诊"且付费面诊；没有"不面诊"/"沿用原报告"，缴费卡不能选免除
  - **基础资料新增了医美史**（选填栏"新增医美史"）→ 提示"有新增医美史，建议面诊"，默认面诊并付费，室长可改
  - **1 个月内** → 面诊 / 不面诊 / 沿用原报告 三选一
  - **沿用原报告**：不产生面诊费卡片，直接进"项目确认中"（**项目确认中的进入方式新增：从接待中直接进入（沿用原报告）**）；面诊资料tab只读显示原报告（标注"沿用自 A000xxx"）；项目列表按原方案预填，价格按现在的项目库重取
  - **面诊**（付费或免除）：缴费卡默认预选"免除面诊费 + 延续既往面诊"（超期/新增医美史时默认付费）；**所有延续既往面诊的面诊多一步"有无变动"**（演示按钮"模拟院长判断：无变动 / 有变动"）：无变动 → 沿用原报告 → 项目确认中（不经过等待报告，面诊费卡照常显示）；有变动 → 视频：等待报告 → 室长上传新报告；书面：直接出新报告 → 项目确认中
  - 原案件保持终态不变，只在它的关联案件tab里出现反向记录
- 面诊费在"面诊预约"里缴纳或免除，不单独设状态

## 03 面诊
**首次面诊**（2026-10-01 修正：面诊方式到时间由 KR 决定，待写入 Notion）
```
面诊预约（待缴费 → 待确认面诊时间）
  → KR 确认面诊时间（不区分视频/书面）→ 等待面诊（显示已确认的时间和倒计时）
  → 到时间后 KR 选择：
     ├ 视频 → IN 端出现"进入面诊" → 面诊进行中（通话中）→ 结束通话（事件：面诊已结束，AI记录+录像）→ 等待报告（等待室长提交报告）→ 室长上传报告 → 项目确认中
     └ 书面 → IN 端立刻收到提醒"院长选择书面面诊" → 面诊进行中（书面面诊中）→ 室长提交报告（院长书面报告 + 室长整理）→ 直接出报告 → 项目确认中（不经过等待报告）
```
- 到时间 KR 没操作的情况，系统不做处理
- 二次面诊流程同上：到时间由 KR 选视频/书面，结束（视频）/进行中（书面）后判断"有无变动"（2026-10-01 修正）
- 面诊形式由 KR 室长到时间决定，IN 和客户不能预选
- **面诊费**：已缴费 / 免除（必选原因，2026-10-01 选项补齐为：复诊 / 术后管理 / 延续既往面诊 / 前次面诊补充 / 术后复查 / 其他；关联原因是复诊/术后管理/延续既往面诊时，缴费卡片默认预选"免除面诊费"+对应原因，室长可改，原因仍必填）/ 面诊取消
- **室长商谈**：出报告后可在案件对话房邀请上传报告的 KR 室长视频，次数不限，不改主状态

**面诊取消**
- 面诊取消 → 是否做本地项目？是 → 选择项目（07）；否 → 已取消（面诊取消）
- 面诊费由当地自行处理，系统只记录状态；之后要面诊走"增加面诊"

**二次面诊**（子流程，**不改案件主状态**，在面诊资料tab内按轮次切换）
- 由 IN 室长判断收费或免费（可先与 KR 室长商量）：收费 → 点"再次面诊" → 待缴费 → 约时间；免费 → 在案件对话中约定 → 约时间
- KR 选视频/书面 → 判断"有无变动"：**无变动** → 本轮直接结束，维持原报告和项目；**有变动** → 视频：等待报告 → 室长上传新报告（同时更新可选范围）；书面：直接出新报告（同时更新可选范围）
- 只需要补加可选项目、不需要重新商谈时，不走二次面诊，KR 室长在对话中直接补加

**增加面诊**（不面诊的案件后来要面诊）
- 付款前点 → 主状态进入"面诊预约"走正常流程；付款后点 → 面诊资料tab内子流程，主状态不变；点击后案件对 KR 可见

## 04 项目确认
- 报告出来即进入"项目确认中"；KR 室长同时给出**可选范围**（赴韩项目 + 术后管理项目，可写项目备注和整体备注，如"颧骨缩小：不可与下颌角同时做"）
- 赴韩项目只能从可选范围里选；范围外的项目在对话里请 KR 补加（免费），需要重新商谈才走二次面诊
- 本地项目显示完整项目库，可选个数和折扣（可写备注）
- 不自动预勾选，由 IN 室长自由勾选
- 结算备注（IN 室长选填）：赴韩项目卡（KR+IN可见）/ 本地项目卡（仅IN可见）/ 整体备注（KR+IN可见）
- **客人不做项目**：按钮 → 二次确认 → 仅出报告
- 不面诊的案件要做赴韩项目，必须先"增加面诊"

## 05 支付与退款
**正常支付**
- 结算 → 小状态"待付款" → 付款：赴韩项目付定金，本地项目付全款；结算单分开列（韩元 / 印尼盾）
- 付款后：有赴韩项目 → 施术预约（06）；本地项目全部转为客户持有项目（07）

**加项**
- 生成新结算单，案件主状态不变；赴韩项目只能从可选范围里选
- 案件已有赴韩项目 → 不重新排期；没有 → 付定金后进入施术预约
- 追加的本地项目直接转为持有

**流程中的退款**（入口：结算单上的［取消项目］）
- 勾选"未开始"的赴韩项目 → 退款弹窗（金额手动填，可为0；**退款原因必填**）→ 项目已取消；结算单部分/全额退款
- 还有赴韩项目 → 继续；没有了 → 是否做本地管理？是 → 同案件进入07；否 → 仅出报告
- 退款由 IN 室长手动决定退不退、退多少，系统不自动判断；金额参考项目快照
- **已到医院之后，IN 不能再取消项目**，只能由 KR 发起（无法施术 / 更换项目）
- 本地项目的退款在客户详情"持有项目"卡片按批次操作（见07），不在案件里

**更换项目**
- = 加项 + 原项目更换；韩国发生由韩国侧操作，印尼发生由印尼侧操作；原项目名划线 + "更换为XX"
- **（2026-10-01，待写入 Notion）更换项目不并入原结算单**：原项目留在原结算单标"已更换"，新项目另开一张新结算单（新tab）；到医院之后的更换，新结算单不收定金，金额直接计入尾款

## 06 赴韩施术
**施术预约**
- 付款后 → 施术预约：IN 室长在月历里选首选+备选**日期**（只能选 KR 已开放的日期）→ 递交 → 待确认施术时间
- KR 室长定具体时间 → 赴韩施术（✓ 施术时间已确认）→ IN 室长转告客人
- KR 无法安排 → 回到选日期，双方在对话里协商，由 IN 室长修改
- 确认后可修改日期（施术前2周截止）→ 变更待确认，原日期继续有效；可取消修改；KR 排不上时双方商量
- **无法协调**（IN 手动操作）→ 取消赴韩项目 + 退款（2026-10-01 修正：不再自动作废术后管理，术后管理按本地项目规则）。赴韩项目全取消后的结局：有本地项目/术后管理 → 保留（再问是否做本地项目：是 → 选择项目/本地管理，否 → 已结案）或全部退款（整批退，填金额+原因 → 仅出报告）；没有 → 问"是否增加本地项目"（是 → 本地管理 → 已结案，否 → 仅出报告）。通则：仅出报告 = 没有任何购买；有购买 = 已结案

**在韩国（全部由 KR 端操作或判断，IN 只看结果 / 按 KR 判断操作，2026-10-01 更新）**
```
已到医院 → 是否能施术？
  ├ 能 → 项目有变动吗？
  │    ├ 没有 → 付清尾款 → 施术完成
  │    └ 有（部分不能做 / 更换项目等）→ 调整项目 → 多退少补、结款 → 是否更改施术时间？
  │          ├ 否 → 施术完成
  │          └ 是 → 回到"施术时间已确认"（新时间）
  └ 不能（KR 判断）→ 能否更改时间后继续？
       ├ 能 → KR 在韩重新预约施术时间 → IN 端显示更改时间 → 回到"施术时间已确认"
       └ 不能 → 退定金（全部退回 / 不退，由 KR 室长判断）→ IN 室长按 KR 判断在系统里操作 → 仅出报告
施术完成 → 有无术后管理？有 → 确认术后管理项目（可变更）→ 标注进行时间 → 已结案；无 → 已结案
```
- **部分项目不能做算"能施术"**：KR 把不能做的项目标"无法施术"（该项目 → 已取消），尾款按实际要做的项目重算、定金先抵；定金不够在韩国补尾款（最常见），定金多了退差额（金额由 KR 判断，IN 操作）；最终已结案
- **尾款公式（2026-10-01 确认，待写入 Notion）**：尾款 = 实际做的项目合计 −（定金合计 − 到医院前已退金额）；到医院之后不单独退款，差额在尾款里多退少补；到医院前在结算单［取消项目］退过的金额只从定金里扣一次，不重复扣减；"付清尾款"是标记完成的前置条件（到院 → 付尾款 → 做 → 结案）
- **到医院之后改时间**：只有 KR 能改（在韩重新预约），IN 不能改；改完回到"施术时间已确认"，客人再到医院时 KR 重新标记"已到医院"
- **到医院之后的退款金额**：由 KR 室长判断，IN 室长只按 KR 的判断在系统里操作（到医院之前仍由 IN 室长决定）；退款弹窗提示"金额按 KR 室长判断填写"
- 各赴韩项目的"已完成"由 KR 标注（可逐个或批量）
- 施术完成时 KR 确认术后管理项目（可修改）并标注每项的进行时间（如术后第7天）；在韩国补加的术后管理项目由 KR 当场代收，标"KR代收"，在印尼不再付款（对账方式暂定）
- 全部赴韩项目都是已完成或已取消 → 系统按08自动判断结局

## 07 本地管理
**流程**（本地案件；或面诊/赴韩案件里点"+添加本地管理"后——这时主状态不变，只显示小标签"本地管理进行中"）
```
选择项目：是否持有项目？
  ├ 是 → 是否使用？
  │    ├ 是 → 勾选项目 → 使用（扣次数）→ 本地管理（项目逐个/批量标完成或取消）
  │    └ 否 → 是否选购？
  └ 否 → 是否选购？
           ├ 是 → 结算付款（转为持有）→ 是否使用？是 → 使用；否 → 结束
           └ 否 → 结束
结束时按08判断：本次有购买或完成了管理 → 已结案；都没有 → 已取消
```
- 本地项目的取消（管理取消）只把没做的次数归还持有，**不是退款**
- 使用了术后管理项目时，本案件自动关联原赴韩案件，对 KR 可见（只读），一直跟踪到这批术后管理项目用完
- 不面诊的案件 KR 看不到；点"增加面诊"后可见

**持有项目规则**
- 本地项目（含"术后管理"分类）按个数购买，买完转为客户持有，不进入案件进程
- 使用：只在"本地管理"里使用；只能用在同一个项目上；先扣最早的批次；术后管理项目置顶，并按 KR 标注的进行时间排序
- 选购时如果已持有同一项目，只提示"持有 X 次"，不抵扣
- 被取消的使用 → 次数归还
- 退款：在客户详情"持有项目"卡片按**批次整批**退，只有完全没用过的批次可退；填金额 + 原因（必填）；该批次作废；不影响任何案件结局
- 暂不设有效期
- 客人来使用持有项目（含术后管理）= 新的预约来访、新的案件

## 08 结案
**判断标准：按客人得到了什么**（退多少钱不影响结局）
- **已结案**：本次完成了施术或管理，或者本次买了本地项目
- **仅出报告**：只完成了面诊（出了报告），没有完成施术或管理，也没有买本地项目
- **已取消**：没出报告、没有完成施术或管理、也没有买本地项目；取消原因：预约取消 / 未到店 / 面诊取消 / 管理取消 / 未购买未使用

**结案对照**
- 8-1 面诊取消，且不做本地项目 → 已取消
- 8-2 面诊后不做项目，或赴韩项目全额/部分退款（且没做本地）→ 仅出报告
- 8-3-1 赴韩施术完成 → 已结案；8-3-2 部分赴韩项目完成、其余退款 → 已结案
- 8-4-1 使用项目 → 管理完成 → 已结案
- 8-4-2 使用取消：部分 → 已结案；全部且本次无购买 → 已取消；全部且本次有购买 → 已结案（没做的次数都归还）
- 8-4-3 本次未使用：有购买 → 已结案；无购买 → 已取消

**附带规则**
- **财务结果**是独立字段：无收入 / 仅面诊费 / 有项目收入 / 全额退款；免除面诊费且没有项目收入 → 无收入；在列表单独一列显示，可按"有退款"筛选
- 案件进入终态时，关联的后续预约全部自动取消
- KR 看到过的案件，之后被取消仍然可见，显示"已取消"

## 09 特殊情况
- **术后面诊 / 复诊**：原案件已结案 → 新预约来访开新案件，关联原案件，面诊费免除（术后复查）；未结案 → 走03的二次面诊
- **术后出现并发症**：新建案件走面诊（免面诊费），之后按正常流程
- **更换项目**：见05
- **面诊后过几天才决定做**：新案件"关联之前案件"（延续既往面诊，自动带出报告），面诊费免除
