# Case Management Flow — 案件状态流程

## ID 规则
```
Reservation ID（6位数字+REV）
  ↓（基础资料确认后）
Case ID（英文+6位数字，如A000001）
```
待确认：Reservation ID 在生成 Case ID 之后是作废还是作为历史字段继续挂在案件上，还没定（Case ID 生成前显示 Reservation ID 这一点已确认，不受影响）。

## 待访问之前：预约与预约占位
- 新客人（室长发链接）：电话预约/到访预约 → 室长发送预约链接 → 工作台日历出现15分钟的"预约占位" → 客户提交 → 生成 Reservation ID → 待访问。占位**不是案件状态**：超时（15分钟）未提交，占位取消，不产生任何案件记录
- 新客人（官网自助）：客户在印尼诊所官网直接打开预约链接 → 预约占位 → 提交 → 生成 Reservation ID → 待访问。对外公开预约页的设计仍"刻意搁置"
- 老客人：客户自主预约，或室长代替预约，不经过占位，直接生成 Reservation ID，进入"待访问"
- 详见 Page Structure / IN-DASH-01 工作台

## 主线（happy path，2026-09-29 第九轮按"项目列表/赴韩施术/本地管理重构"指令改）
```
待访问
  ↓ 客户到访（= 接待中，不单独设状态）
接待中（基础资料确认时生成Case ID，同时决定是否需要面诊；意向项目+预算这时候一起填，见下）
  ↓ 需要面诊
等待面诊 → …（面诊形式见分支4）→ 已出报告（KR室长同时给出赴韩可选项目范围krScope）
  ↓
项目确认中（IN室长：从krScope选赴韩项目、从完整项目库选本地项目 → 确认）
  ↓ 确认后立即生成结算单，不管有没有赴韩项目
待付款
  ↓
已付款
  ├─ 有赴韩项目：递交施术日期 → 待确认施术时间 → 等待施术 →（"已到医院"触发）赴韩施术中
  └─ 只有本地项目：直接进本地管理中（不用等"已到医院"这个赴韩专属触发点）
  （两种项目都有的案件：本地项目照常推进，不需要等赴韩排期）
  ↓
已结案
```
- 赴韩施术：已到医院 → 付清尾款（在韩国）→ 施术完成 → 有术后管理则进入术后管理，否则结案
- 本地管理：按项目逐条约"到店日期+时间"，进度 已预约到店→已到店→管理中→完成；约好的时间显示在工作台日历（事件类型复用"术后管理"），不生成新Reservation ID、不开新案件（原来的 open-questions 第3条已解决，见该文档）
- ⚠️ 已废弃（2026-09-29 第九轮）：旧版"待确认施术时间（KR室长确认施术时间）→ 确认后生成结算单 → 待付款"——施术排期原来在结算/付款**之前**；现在改成先生成结算单→付款，施术日期挪到**付款之后**才递交，不再是结算前的门槛

## 意向项目 / 预算（2026-09-29 新增，基础资料tab）
- 客人到店时，除了苦恼/希望预期，还要填"意向项目"（必填，赴韩+本地项目库都能多选）和"预算"（选填，印尼盾区间）
- 这两项带进面诊资料tab展示，KR室长可见，作为面诊和赴韩可选范围整理的参考

## 赴韩项目可选范围 krScope（2026-09-29 新增，替代原来"院长推荐"整份指令）
- 出报告的同时，KR室长直接整理出赴韩项目的可选范围（不经过院长），可以带项目备注（例如"颧骨缩小：不可与下颌角同时做"）和整体备注
- 项目列表tab的"赴韩项目"子tab只显示 krScope 里的项目；没有krScope（还没出报告/不面诊案件）显示引导空状态，不面诊案件额外给"增加面诊"入口
- KR室长可以随时（结算前、加项时）更新可选范围，往里加项目
- "本地项目"子tab不受krScope限制，照常显示完整项目库
- 不做自动预勾选，由IN室长自由勾选（这条要求本身保留，"院长推荐只读卡片"那份指令其余部分作废）

## 施术日期规则（2026-09-29 重写，原"施术预约规则"整节作废，规则变了：从结算前移到已付款之后）
- 已付款、且有赴韩项目的案件，才会出现"施术日期"这一步（本地项目跟施术日期无关）
- IN室长可填首选+备选两个日期（只选日期不选具体时间），只能选KR室长已开放的日期
- 递交后等KR室长确认（回复确认日期+具体时间）或回复两个日期都不行（回到可重新选日期）
- 确认后（等待施术）可修改日期，截止施术前2周：chat协商后由IN室长提交新日期 → KR室长重新确认；等待期间主状态不变，界面显示"时间变更待确认"
- 无法协调（不管是初次排期还是修改后）：取消该次排期涉及的全部未完成赴韩项目，退还定金 → 还有本地项目：案件继续，转入本地管理；没有本地项目：案件转为已取消（全额退款）
- ⚠️ 已废弃：旧的"付款前时间始终无法协调 → 仅本地项目继续 / 仅出报告"这套——排期现在在付款之后才发生，不会再出现"付款前协调失败"这种情况

## 终态（共4种）
- **已结案**：施术 / 术后管理全部完成
- **已结案（部分退）**：部分项目已开始/完成，剩余项目取消退款
- **已取消**：由"取消原因"字段区分 ①预约取消 ②面诊取消且不做本地项目 ③全额退款（所有项目取消）
- **仅出报告**：已出报告，但既不赴韩也不做本地项目
- 进入"已取消（全额退款）"或"已结案（部分退）"时，该案件关联的后续预约全部自动取消
- 列表tab归属规则（看案件怎么结束的）：流程自然走完、中途没有取消动作 → "已结案"tab（已结案 / 已结案（部分退）/ 仅出报告）；中途有取消动作 → "已取消"tab（预约取消 / 面诊取消 / 全额退款）。列表状态标签显示具体终态
- 韩国侧可见性：韩国侧看到过的案件，面诊取消后仍可见，显示为"已取消"
- ⚠️ 已废弃：终态"已取消预约""已取消（全退）"分开命名——并入"已取消"+取消原因

## 分支1 — 预约到访阶段直接终止
```
待访问 → 取消预约 → 选择取消原因 → 已取消（取消原因：预约取消；资料保留，终态）
```

### 取消接待（2026-09-29 新增，区别于上面的"取消预约"）
```
接待中（Case ID 生成前）→ 取消接待 → 弹窗二次确认 → 待访问（非终态，可重新到访）
```
- 只在基础资料确认、生成 Case ID 之前可用；确认弹窗："确认取消吗？取消后内容不保存。"
- 确认后丢弃本次已填写的메타뷰/照片/视频/苦恼/希望预期/面诊需求草稿，案件回到"待访问"，工作台日历对应的预约来访恢复原色、去掉"已到访"标记，Timeline 记一条"取消接待"事件
- 和分支1的"取消预约"不是一回事："取消预约"发生在客人到店之前、是终态；"取消接待"发生在客人已到店、资料还没确认完时，不是终态，只是把接待流程复位

## 分支2 — 不需要面诊
```
接待中（基础资料确认时选"不面诊"）→ 项目确认中 → 待付款 → 已付款 → 本地管理中 → 已结案
```
- 不面诊的案件，韩国侧完全看不到
- 案件头部显示"增加面诊"按钮，结案前都可用：付款前点击 → 主状态进入"等待面诊"走正常面诊流程；付款后点击 → 作为子流程在面诊tab进行，主状态不变；点击"增加面诊"后，案件对韩国侧可见

## 分支3 — 面诊取消
```
等待面诊 → 面诊取消 → 是否做本地项目？
  ├─ 是 → 按分支2（不面诊）继续
  └─ 否 → 已取消（取消原因：面诊取消）
```
- 面诊费由当地自行处理，系统只记录状态，不走钱
- 之后如需再面诊，走"增加面诊"
- ⚠️ 已废弃：等待面诊 → 面诊取消（可重新点"面诊申请"）→ 回到 等待面诊

## 分支4 — 面诊形式（由韩国室长决定，不是IN或客户提前选）
```
等待缴纳面诊费 → 等待确认面诊时间（等待韩国室长确认面诊形式与时间）

视频路径：→ 等待面诊（视频面诊时间已确定）→ 面诊进行中 →（事件：面诊已结束，自动生成AI记录+保存视频）→ 等待报告 → 已出报告

书面路径：→ 等待报告（室长已给出书面结论，等待提交正式报告；预计提交时间由室长回复时一并给出）→ 已出报告
```
- "面诊已结束"只作为Timeline事件，不是停留状态；视频、书面两条路径在出报告前统一为"等待报告"（原书面路径的"报告待递交"更名为"等待报告"）
- 已出报告后可选"室长商谈"：在案件对话房内发起视频，选择上传了报告的室长，结束后生成AI记录+保存视频，不改变主状态，次数不限（见 Conversation & Video Flow）
- ⚠️ 已废弃（2026-09-29 第七轮）："等待面诊"原来一并指"已缴费、等KR室长确认形式与时间"这一段，视频路径的"面诊已排期"是单独状态名——现在拆成两个主状态："等待确认面诊时间"（缴费后，等KR室长回复面诊形式与时间）和"等待面诊"（专指视频路径，视频面诊时间已确定）

## 分支5 — 二次面诊
由印尼室长判断走哪条路径（可与韩国室长商议后决定）：
```
收费路径：已出报告 → 点"再次面诊" → 弹窗"确认再次申请吗？" → 确认 → 等待缴纳面诊费 → 预约第二次面诊时间 → …
免费路径：已出报告 → 在案件对话中约定 → 预约第二次面诊时间 → …

共同后续：等待面诊 → 面诊进行中 →（面诊已结束，AI记录+保存视频）→ 有无变动？
  ├─ 有 → 等待报告 → 已出报告（→ 可选室长商谈）
  └─ 无 → 不出新报告，继续原流程
```
- 二次面诊一律为视频面诊
- 二次面诊是子流程，进度只在面诊tab显示，**案件主状态不变**
- "再次面诊"按钮在已出报告后显示，结案前都可用
- 术后面诊：案件未结案 → 走本分支；案件已结案 → 走01预约流程新建案件，免除面诊费
- ⚠️ 已废弃：已出报告 → 点"再次面诊"（二次确认+重新收一次面诊费）→ 回到 等待面诊 → 重新走一遍分支4

## 分支6 — 已付款之后的取消/退款（按项目）
```
项目未开始 → 取消项目 → 退款 → 退款完成
部分项目已开始 → 取消剩余项目 → 退还剩余金额
```
- 全部项目取消并退款 → 已取消（取消原因：全额退款）
- 部分项目已完成、剩余项目退款 → 已结案（部分退）
- 两种终态都会自动取消该案件关联的后续预约
- 退款金额规则：赴韩项目只退已收的预付金，本地项目退全款（金额以案件内的项目快照为准，不回项目库查价）
- ⚠️ 已废弃：项目按"结算批次"管理，每批次独立判断（整批全退/整批部分退）——退款改为按单个项目判断

## 分支7 — 更换项目
```
已付款 → 增加项目（分支8）→ 原项目部分退款（分支6）
```
- 在韩国发生的更换由韩国侧操作，在印尼发生的更换由印尼侧操作
- 展示：原项目名划线 + 标注"更换为XX项目"
- ⚠️ 已废弃：不是案件级状态分支，案件仍留在"赴韩施术中"，印尼侧只能看不能改——改为加项+部分退款、双方各自操作

## 分支8 — 加项（2026-09-29 第九轮重写）
```
已有案件 → 新增项目（赴韩只能从krScope选）→ 结算、付定金 → …
```
- 案件主状态保持当前位置不变
- 案件里已经有赴韩项目：新加的赴韩项目并入已有的施术日期安排，不用重新走一遍排期
- 案件里还没有赴韩项目（原来是纯本地案件）：付款后正常走一遍"施术日期规则"
- 赴韩项目和本地项目一起结算，但结算单分开列（赴韩项目韩元 / 本地项目印尼盾）
- ⚠️ 已废弃（2026-09-29 第九轮）："新增赴韩项目时先预约施术时间→KR室长确认→再生成新结算单"——排期挪到付款之后，加项不再需要先排期才能结算

## 分支9 — 出报告后不做项目
```
已出报告 → 项目确认中：不赴韩，也不做本地项目 → 仅出报告（终态）
```
- 【待确认，2026-09-29 第九轮】原来的触发路径是"付款前施术时间始终无法协调、且没有本地项目"——但排期挪到付款之后，这条触发路径已经不存在了（现在同样的情况会走"施术日期规则"的"无法协调"，结果是"已取消（全额退款）"，不是"仅出报告"）。目前代码里没有任何操作会把案件转成"仅出报告"，这个终态暂时没有活的触发入口，需要向你确认：这个终态还要不要保留、要的话新的触发条件是什么
