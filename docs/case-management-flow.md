## 待访问之前：预约与预约占位
- 新客人（室长发链接）：电话预约/到访预约 → 室长发送预约链接 → 工作台日历出现15分钟的"预约占位" → 客户提交 → 生成 Reservation ID → 待访问。占位**不是案件状态**：超时（15分钟）未提交，占位取消，不产生任何案件记录
- 新客人（官网自助）：客户在印尼诊所官网直接打开预约链接 → 预约占位 → 提交 → 生成 Reservation ID → 待访问。对外公开预约页的设计仍"刻意搁置"
- 老客人：客户自主预约，或室长代替预约，不经过占位，直接生成 Reservation ID，进入"待访问"
- **客人来使用持有项目（含术后管理）：同样走这条"预约来访"，开新案件，不走别的入口**（2026-09-30 新增，见下"案件定义与持有项目"）
- 详见 Page Structure / IN-DASH-01 工作台

## 案件定义与持有项目（2026-09-30 第十轮新增，改变了终态判定方式）
- **一个案件 = 一次到店或一次赴韩旅程**。赴韩案件：KR标记"施术完成"即结案；只做本地项目的案件：本次使用完成（或选"本次不使用"）即结案
- 本地项目（含"术后管理"这个新分类）结算后**立即转为客户持有项目**，不进入案件进程、不影响结案判定——这一点和赴韩项目完全不同，赴韩项目还是挂在案件的施术链里
- 已到医院 / 付清尾款 / 施术完成，三步都由KR端操作，IN端只显示状态（原型用演示按钮模拟）
- 持有项目结构：`client.holdings = [{itemName, category, batches:[{caseId, date, bought, used, usages:[{caseId, date, qty}]}], krCollected}]`，按客户存，不挂在具体案件下
  - 按个数购买，买完转持有；只能用在同一项目上，不能换抵；多批时先扣最早购买的那一批
  - 使用它的案件或项目被取消 → 扣掉的次数退回持有（只退次数，不退钱）——**原型这轮只实现了"使用即扣"的正向流程，反向的"退回持有"没有对应UI入口，见 open-questions**
  - 每次使用记案件Timeline"使用了XX N次，剩余M次"，并计入客户详情"本院项目记录"
  - 暂不设有效期；退款只适用于**赴韩项目**（退定金），本地项目（含术后管理）一律不退，未使用的也不退（涉及医疗纠纷风险）
  - 术后管理项目来源：KR室长整理可选范围时一并写入，客人在印尼结算购买；到韩国后需要补加的由韩国侧代收，标注"KR代收"，在印尼不再付款
- ⚠️ 已废弃（2026-09-30）："术后管理中(local)"状态、结算后的"施术顺序"步骤——案件里现在只剩赴韩项目，不需要排序；本地项目管理进度改为在客户持有项目里跟踪，不再是案件tab（原"本地管理"tab整节取消）
- ⚠️ 已废弃（2026-09-30）：术后到店/使用持有项目走案件内的"本地管理"tab约到店、联动日历"术后管理"事件类型——现在统一走"预约来访"开新案件，不再使用这个事件类型

## 主线（happy path，2026-09-30 第十轮按"持有项目/案件结案/赴韩施术调整"指令改）
```
待访问
  ↓ 客户到访（= 接待中，不单独设状态）
接待中（基础资料确认时生成Case ID，同时决定是否需要面诊；意向项目+预算这时候一起填，见下）
  ↓ 需要面诊
等待面诊 → …（面诊形式见分支4）→ 已出报告（KR室长同时给出赴韩可选项目范围krScope，含术后管理项目）
  ↓
项目确认中（IN室长：从krScope选赴韩/术后管理项目、从完整项目库选其他本地项目 → 确认）
  ↓ 确认后立即生成结算单，不管有没有赴韩项目
待付款 → 已付款
  ├─ 有赴韩项目：递交施术日期 → 待确认施术时间 → 等待施术 → （KR标记"已到医院"）赴韩施术中
  │                                            → （KR标记"付清尾款"）→ （KR标记"施术完成"）→ 已结案
  └─ 只有本地项目：本地项目立即转客户持有 → 管理进行中（待使用）→ 使用持有项目/本次不使用 → 已结案
```
- 不需要面诊的案件：接待中确认后直接给两个入口——「持有项目使用」（勾选已持有的项目，填本次次数，使用后结案）/「新增项目"（只显示本地项目，结算→持有项目使用→使用→已结案，也可"本次不使用"直接结案）
- 两种项目都有的案件（面诊路径里同时选了赴韩+本地）：本地项目结算后照常转客户持有，不需要等赴韩这边的排期/已到医院

## 意向项目 / 预算（基础资料tab）
- 客人到店时，除了苦恼/希望预期，还要填"意向项目"（必填，赴韩+本地项目库都能多选）和"预算"（选填，印尼盾区间）
- 这两项带进面诊资料tab展示，KR室长可见，作为面诊和赴韩可选范围整理的参考

## 赴韩项目可选范围 krScope
- 出报告的同时，KR室长直接整理出赴韩项目的可选范围（不经过院长），术后管理项目也一并写入，可以带项目备注（例如"颧骨缩小：不可与下颌角同时做"）和整体备注
- 项目列表tab的"赴韩项目"子tab只显示 krScope 里的赴韩项目；没有krScope（还没出报告/不面诊案件）显示引导空状态，不面诊案件额外给"增加面诊"入口
- "本地项目"子tab里，普通本地项目不受krScope限制、照常显示完整项目库；**"术后管理"分类的项目和赴韩项目一样，只能从krScope里选**
- KR室长可以随时（结算前、加项时）更新可选范围，往里加项目（演示：模拟KR室长更新可选项目）
- 不做自动预勾选，由IN室长自由勾选

## 本地项目结算细节（2026-09-30 新增）
- 每行本地项目可填个数、折扣（如90%）、备注；结算单同时显示原价和折后价
- 客户已持有同一项目时，项目名后显示"持有 X 次"（信息提示，不在这里直接扣）；真正的扣减发生在"持有项目使用"这一步
- 结算区：一张大卡包两张二级卡——赴韩项目卡（合计₩+定金₩，备注KR+IN可见）/ 本地项目卡（含术后管理，全款Rp，备注仅IN可见）；哪边没选就隐藏哪张卡，不显示两边相加总计；结算区上方还有一个整体备注（KR+IN可见）

## 施术日期规则（已付款之后才发生，不再是结算前的门槛）
- 已付款、且有赴韩项目的案件，才会出现"施术日期"这一步（本地项目跟施术日期无关）
- IN室长可填首选+备选两个日期（只选日期不选具体时间；2026-09-30 起首选和备选合成一个月历：第一次点击是首选，第二次点击是备选，颜色不同，再点一次已选日期取消选择），只能选KR室长已开放的日期；月历默认打开的月份：首次递交时是最近的可选月份，修改日期时是原定日期所在的月份
- 递交后等KR室长确认（回复确认日期+具体时间）或回复两个日期都不行（回到可重新选日期，原草稿清空重选）
- 确认后（等待施术）可修改日期，截止施术前2周：
  - IN室长提交新的首选/备选日期 → 等KR室长确认；等待期间原确认日期继续有效，界面显示"时间变更待确认"
  - 提交新日期旁边有「取消修改」，点击直接回到"等待施术"，原日期不变
  - **KR排不上新日期时不自动取消**：点"模拟KR无法确认"只是回到可以重新选日期的状态，原日期继续有效，IN室长可以再改再递交
  - 只有IN室长手动点「无法协调」，才会取消这次排期涉及的全部未完成赴韩项目、退还定金
- 无法协调的后续（2026-09-30 更正）：取消赴韩项目并退款（退多少由室长手动填，退款原因必填）→ 问客人要不要做本地管理：要 → **同一个案件里**接着走分支2（从"是否持有项目"开始）；不要 → 按结局推算（没买本地项目 → 仅出报告）
- ~~无法协调：清空未完成赴韩项目后直接判"已取消（全额退款）"~~ ⚠️ 已废弃（2026-09-30）：客人已拿到报告，不能算取消
- ⚠️ 已废弃：旧的"付款前时间始终无法协调 → 仅本地项目继续 / 仅出报告"这套——排期现在在付款之后才发生，不会再出现"付款前协调失败"这种情况
- ⚠️ 已废弃（2026-09-30）：IN端「标记已到医院」按钮——已到医院改由KR端操作（演示按钮模拟）

## 终态（2026-09-30 最终版：只保留 3 种，结局由系统在案件结束时推算）
判断标准是"**客人得到了什么**"，退多少钱不影响结局：
- **已结案**：本次完成了施术或管理，或者本次买了本地项目
- **仅出报告**：只完成了面诊（有报告），没有完成施术或管理，也没有买本地项目（赴韩项目全额/部分退款后同样适用）
- **已取消**：没出报告，没有完成施术或管理，也没有买本地项目；取消原因：预约取消 / 面诊取消 / 管理取消 / 未购买未使用
- **财务结果**（独立字段 `financeResult`）：无收入 / 仅面诊费 / 有项目收入 / 全额退款；与结局一起显示为标签（如"仅出报告 · 有项目收入 ₩300,000"）；发生过退款另显示退款金额，案件列表可按"有退款"筛选
- 列表tab：全部 / 预约到店 / 面诊安排 / 赴韩施术 / 管理进行中 / 已结案 / **仅出报告** / 已取消（共 8 个，另有"有退款"筛选）
- 进入终态时，该案件关联的后续预约全部自动取消（Notion 规则；原型未实现自动取消后续预约这一联动）
- 韩国侧可见性：韩国侧看到过的案件，面诊取消后仍可见，显示为"已取消"
- ~~终态共4种：已结案 / 已结案（部分退）/ 已取消（含"全额退款"原因）/ 仅出报告~~ ⚠️ 已废弃（2026-09-30）：改为按客人得到了什么判断，退款入财务字段
- ~~列表tab归属规则：流程自然走完→已结案tab；中途有取消动作→已取消tab~~ ⚠️ 已废弃（2026-09-30）：三个终态各一个tab

### 08 结案对照
- 面诊取消且不做本地项目 → 已取消
- 面诊后不做项目，或赴韩项目全额/部分退款（且不做本地）→ 仅出报告
- 赴韩施术完成 → 已结案；部分赴韩项目完成、其余退款 → 已结案
- 使用项目 → 管理完成 → 已结案；部分使用取消 → 已结案；全部使用取消且本次无购买 → 已取消（管理取消）；全部使用取消且本次有购买 → 已结案（未做次数归还持有，不是退款）
- 本次未使用但有购买 → 已结案；本次未使用也无购买 → 已取消（未购买未使用）

## 案件关系与同日本地管理（2026-09-30 新增）
- 一次预约 = 一个案件；另一天来要重新预约、开新案件；同一客户可同时有多个进行中的案件
- 同天插做本地项目：面诊/赴韩案件从生成Case ID到结案前，案件页右上角「发起对话」旁有「+ 添加本地管理」（不面诊的案件不显示）→ 出现"本地管理"tab，复用分支2的本地流程 → 案件主状态不变，状态栏在主状态旁加小标签"本地管理进行中"；Timeline记录每一步；本地管理里的购买和使用算进结案时的结局判断
- 关联（不同天的案件之间）：接待时基础资料"关联之前案件"（下拉只列该客户以前的案件）+ 关联原因（复诊 / 术后管理 / 延续既往面诊）；新案件标题下显示"关联：A000010（复诊）"可跳转，原案件显示"后续关联案件"；复诊/延续既往面诊时原面诊报告自动带入新案件附件；系统提示"可能与 XX 相关"（客户有最近结案的赴韩案件，或还有没用完的术后管理项目）；在新案件里使用某案件的术后管理项目时自动建立关联

## 分支1 — 预约到访阶段直接终止
```
待访问 → 取消预约 → 选择取消原因 → 已取消（取消原因：预约取消；资料保留，终态）
```

### 取消接待（区别于上面的"取消预约"）
```
接待中（Case ID 生成前）→ 取消接待 → 弹窗二次确认 → 待访问（非终态，可重新到访）
```
- 只在基础资料确认、生成 Case ID 之前可用；确认弹窗："确认取消吗？取消后内容不保存。"
- 确认后丢弃本次已填写的메타뷰/照片/视频/苦恼/希望预期/意向项目/预算/面诊需求草稿，案件回到"待访问"，工作台日历对应的预约来访恢复原色、去掉"已到访"标记，Timeline 记一条"取消接待"事件

## 分支2 — 不需要面诊（2026-09-30 再改：按用户 07 flow，新增"管理进行中"出口）
```
接待中（基础资料确认时选"不面诊"）→ 是否持有项目？
  ├ 是 → 是否使用？ ├ 是 → 勾选项目 → 使用 → 管理进行中
  │                 └ 否 → 是否选购？
  └ 否 → 是否选购？
是否选购？ ├ 是 → 结算付款 → 是否使用？ ├ 是 → 勾选项目 → 使用 → 管理进行中
           │                            └ 否 → 已结案
           └ 否 → 本 case 是否有发生购买？有 → 已结案，无 → 已取消（未购买未使用）
管理进行中：├ 管理完成 → 已结案
            └ 管理取消：部分取消 → 已结案；全部取消 → 有购买→已结案，无→已取消（管理取消）
              （不管哪种取消，没做的次数都归还持有项目，提示"不是退款"）
```
- 每次到店都是一个案件（预约来访开新案件）
- "管理进行中"：使用项目后进入，到管理完成/管理取消为止；列表显示在"管理进行中"tab
- 不面诊的案件，韩国侧完全看不到
- 案件头部显示"增加面诊"按钮，结案前都可用：付款前点击 → 主状态进入"等待面诊"走正常面诊流程；付款后点击 → 作为子流程在面诊tab进行，主状态不变；点击"增加面诊"后，案件对韩国侧可见
- ~~持有项目使用 → 使用 → 已结案；已付款、尚未使用期间显示在"管理进行中"tab~~ ⚠️ 已废弃（2026-09-30）：使用后进入管理进行中；已付款尚未使用期间不再属于管理进行中（原型里暂留在"面诊安排"tab，见 CLAUDE.md 待确认）
- ⚠️ 已废弃（2026-09-30）：接待中 → 项目确认中 → 待付款 → 已付款 → 本地管理中 → 已结案——本地项目现在结算后立即转客户持有

## 分支3 — 面诊取消
```
等待面诊 → 面诊取消 → 是否做本地项目？
  ├─ 是 → 按分支2（不面诊）继续（同样先给"持有项目使用/新增项目"两个入口）
  └─ 否 → 已取消（取消原因：面诊取消）
```
- 面诊费由当地自行处理，系统只记录状态，不走钱
- 之后如需再面诊，走"增加面诊"

## 分支4 — 面诊形式（由韩国室长决定，不是IN或客户提前选）
```
等待缴纳面诊费 → 等待确认面诊时间（等待韩国室长确认面诊形式与时间）

视频路径：→ 等待面诊（视频面诊时间已确定）→ 面诊进行中 →（事件：面诊已结束，自动生成AI记录+保存视频）→ 等待报告 → 已出报告

书面路径：→ 等待报告（室长已给出书面结论，等待提交正式报告；预计提交时间由室长回复时一并给出）→ 已出报告
```
- "面诊已结束"只作为Timeline事件，不是停留状态；视频、书面两条路径在出报告前统一为"等待报告"
- 已出报告后可选"室长商谈"：在案件对话房内发起视频，选择上传了报告的室长（报告由KR室长上传，原型演示数据里 `reportUploadedBy` 为KR室长，候选名单按上传人过滤，2026-09-30），结束后生成AI记录+保存视频，不改变主状态，次数不限（见 Conversation & Video Flow）

## 分支5 — 二次面诊
由印尼室长判断走哪条路径（可与韩国室长商议后决定）：
```
收费路径：已出报告 → 点"再次面诊" → 弹窗"确认再次申请吗？" → 确认 → 等待缴纳面诊费 → 预约第二次面诊时间 → …
免费路径：已出报告 → 在案件对话中约定 → 预约第二次面诊时间 → …

共同后续：等待面诊 → 面诊进行中 →（面诊已结束，AI记录+保存视频）→ 有无变动？
  ├─ 有 → 等待报告 → 已出报告（→ 可选室长商谈）
  └─ 无 → 不出新报告，继续原流程
```
- 二次面诊一律为视频面诊
- 二次面诊是子流程，进度只在面诊tab显示，**案件主状态不变**
- "再次面诊"按钮在已出报告后显示，结案前都可用
- 只需补加赴韩可选项目、不需要重新商谈时，不走二次面诊，由KR室长在对话中直接补加
- 术后面诊：案件未结案 → 走本分支；案件已结案 → 走01预约流程新建案件，免除面诊费
- 二次面诊"有变动"出新报告时，KR室长随新报告给出新的可选范围，自动覆盖 krScope（2026-09-30 用户确认，已实现）

## 分支6 — 已付款之后的取消/退款（按项目；案件里只处理赴韩项目，2026-09-30 更新）

赴韩项目未开始 → 取消项目 → 室长手动填退款金额+退款原因 → 退款完成
