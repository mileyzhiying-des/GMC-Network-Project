# Open Questions — 未定业务规则

来源：Notion「GMC Network」/ Domain Knowledge / Open Questions，导出时间 2026-09-30。
改动下面这些相关功能前，先确认清楚，不要自己替业务方拍板。

## 1. 结算具体比例
结构已确认：赴韩项目收预付金 + 尾款（尾款赴韩后付），本地项目收全款（见 `business-rules.md`）。
**具体预付比例还没定**——用户正在向代表确认，尚未拍板。原型代码里 `KR_DEPOSIT_RATE = 0.3`（30%）只是演示占位数字，不是业务方确认的数字。

## 2. Reservation ID 的生命周期
Reservation ID（6位数字+REV）生成 Case ID（英文+6位数字）之后，前者是作废还是继续作为历史字段挂在案件上——还没定。**Case ID 生成前应该显示 Reservation ID 这一点已经确认（2026-09-29），原型已实现**；只有"Case ID 生成后 Reservation ID 要不要保留"这一半还没拍板。

## 3. "仅出报告"终态还缺"出报告后不做项目"的直接出口
2026-09-30 起"仅出报告"可由赴韩项目全退（含无法协调后客人不做本地管理）触发（按结局推算，已实现）。但分支9"已出报告 → 项目确认中 → 不赴韩也不做本地项目 → 仅出报告"这个直接出口，原型仍没有对应的操作入口，需要业务方确认要不要做、放在哪个界面。

## 4. 持有项目"使用后撤销"没有对应UI
业务规则写的是"使用它的案件或项目被取消时，次数退回持有（不退钱）"。2026-09-30（第十轮）这轮只实现了"使用即扣"的正向流程（`useHolding()`），反向的"退回持有"目前没有任何按钮或入口触发，改动/需要这个功能时先确认具体交互（在哪个页面、谁来操作）。

## 5. 术后管理演示数据是我编的
项目库"术后管理"分类下的两个演示项目（术后消肿护理1次、术后疤痕修复护理1次）及价格是我编的demo数据，不是业务方指定的清单；"模拟KR补加术后管理项目"演示按钮固定选项目库里第一个可用的术后管理项目，这个"选哪个"的演示逻辑也是我的判断。

## 6. 2026-09-30（第十一轮）新增的待确认项
1. 已付款但还没决定是否使用持有项目期间，案件属于哪个列表tab——旧规则（"管理进行中"）已废止，新规则没指定，原型暂放"面诊安排"tab。
2. 财务结果的判定口径（项目收入=已付款批次的赴韩定金+本地全款，赴韩部分扣退款；面诊费按"已缴费"推断，原型没有"面诊费免除"字段）。
3. 客户详情本地项目退款后，该批未使用的次数是否作废、本地退款是否计入案件财务结果——指令没说，原型都没动。
4. "+添加本地管理"里的选购是简化版（勾选项目+个数，没有折扣/备注，结算后直接转持有），不走主结算单。
5. 基础资料里的 메타뷰/照片/视频 移到附件tab后，原来的"再上传/修正"入口没有保留；面诊tab里原有的内联附件块也还在，和附件tab重复显示。
6. 手动上传的附件归到"基础资料"还是"面诊资料"——指令没说，原型按"是否已申请面诊"决定。
7. 已被手动关联的案件，后面使用术后管理项目时不再自动改关联；一个案件只能关联一个之前的案件。
8. 赴韩"无法协调"退款弹窗沿用同一个退款弹窗（金额手动+原因必填），Notion 写"退多少由室长决定"。

## 已解决（保留记录）
- ~~案件管理-预约修改：院长 default 选择逻辑~~ —— 2026-09-23 已解决：默认当前对接院长，可通过下拉框改选其他院长，不需要额外的"最近一次/评分最高"选择算法。
- ~~"已付款"转入施术中的触发时机~~ —— 已解决：确认为"已到医院"，原型已实现（2026-09-30 第十轮改成KR端演示按钮 `simulateKrMarkArrived()` 触发，不再是IN端按钮）。
- ~~已有案件内的到访不开新案件~~ —— 已解决：术后到店/使用持有项目统一走"预约来访"开新案件，不生成额外的案件内到访机制。
  > ⚠️ 这条曾经在"案件流程对齐"那轮被实现成"本地管理tab里按项目约到店+联动日历'术后管理'事件类型"，2026-09-30（第十轮）指令明确废止了那个实现（`localManagementTabHtml()`/`scheduleLocalVisit()`等已删除），改成上面这个更简单的答案：本地项目结算后转客户持有，不再需要案件内到店流程。
- ~~施术前2周内修改日期，KR无法确认新日期时的处理粒度~~ —— 2026-09-30（第十轮）已解决：KR排不上新日期**不自动取消**，回到可重新选日期的状态、原日期继续有效；只有IN室长手动点"无法协调"才会取消全部未完成赴韩项目退定金。原型已实现 `simulateKrScheduleChangeReject()`/`cannotCoordinateKrSchedule()`。
