# Open Questions — 未定业务规则

来源：Notion「GMC Network」/ Domain Knowledge / Open Questions，导出时间 2026-09-29。
改动下面这些相关功能前，先确认清楚，不要自己替业务方拍板。

## 1. 结算具体比例
结构已确认：赴韩项目收预付金 + 尾款（尾款赴韩后付），本地项目收全款（见 `business-rules.md`）。
**具体预付比例还没定**——用户正在向代表确认，尚未拍板。原型代码里 `KR_DEPOSIT_RATE = 0.3`（30%）只是演示占位数字，不是业务方确认的数字。

## 2. Reservation ID 的生命周期
Reservation ID（6位数字+REV）生成 Case ID（英文+6位数字）之后，前者是作废还是继续作为历史字段挂在案件上——还没定。**Case ID 生成前应该显示 Reservation ID 这一点已经确认（2026-09-29），原型已实现**；只有"Case ID 生成后 Reservation ID 要不要保留"这一半还没拍板。

## 3. 施术前2周内修改日期，KR无法确认新日期时的处理粒度
2026-09-29（第九轮）新增"施术日期"规则时，用户原文写的是"取消该项目"（单数），但案件的赴韩施术日期是整案共用一套（krSchedule 挂在案件上，不是挂在单个项目上）。目前的实现判断是：KR无法确认新日期＝等同"无法协调"，取消这次排期涉及的**全部**未完成赴韩项目并退定金。这是我的判断，不是业务方明确拍板的粒度，改动/回退前先确认。

## 4. "仅出报告"终态现在没有活的触发路径
2026-09-29（第九轮）排期改到付款之后才发生，原来"付款前施术时间始终无法协调、且没有本地项目 → 仅出报告"这条路径已经不成立（现在同样情况走"施术日期规则"的"无法协调"，结果是"已取消（全额退款）"）。代码里 `closeNote:'仅出报告'` 这个值和对应的badge/文案还留着，但没有任何操作会把案件转成这个终态了。需要业务方确认：这个终态还要不要保留，要的话新的触发条件是什么。
